# 退出复刻（Unfork Blockly）

## 介绍

当您选择复刻 Blockly 时，您可以快速修改源码，但也会逐步偏离上游版本。退出复刻（Unfork）是把自定义能力迁移回公开 API、插件和可维护扩展点的过程。

这个过程的目标是：

- 减少长期维护成本。
- 恢复上游版本更新能力。
- 避免在私有实现中反复修改 block、field 和渲染逻辑。

## 何时应该考虑退出复刻

如果出现以下情况，建议优先考虑退出复刻：

- 每次升级 Blockly 都需要大量手工合并。
- 自定义逻辑主要集中在工具箱、主题、连接检查器、代码生成器等公开扩展点。
- 团队希望把功能沉淀为插件，而不是长期维护一份 fork。

## 推荐迁移路径

### 1. 列出所有复刻改动

先对当前 fork 做清单，按“可替换到公开 API”与“仍缺公开 API”两类标注。

### 2. 优先迁移到插件和注册机制

将能迁移的改动逐步移到以下机制：

- `Blockly.registry` 注册类与组件。
- 自定义渲染器、连接检查器、工具箱组件。
- 块扩展、mutator 和代码生成器扩展。

### 3. 为缺失 API 提交需求

如果某项能力必须访问非公开成员，建议提交功能请求，推动公开 API 完善，而不是继续加深复刻。

### 4. 分阶段回归上游

每完成一批迁移后，更新到最近上游版本并做回归验证，避免一次性大迁移风险。

## 验收建议

- 能在不改 Blockly 核心源码的前提下完成功能。
- 升级新版本 Blockly 时仅需小规模适配。
- 关键功能具备自动化测试与示例验证。
